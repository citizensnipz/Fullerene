# Glossary - Fullerene

Terms for harness and design discussions. Definitions follow the current repo where code exists.

| Term | Meaning |
|------|---------|
| **Facet** | One of twelve modular components (Memory through Learning); the current v0 terminology uses **Behavior** in place of the earlier confidence/decision placeholder. |
| **Nexus** | Central interpreter/integrator loop that accepts events, asks facets for results, integrates a decision, and persists runtime state/logs. |
| **CycleSignalMap** | Canonical per-cycle Nexus signal packet. It normalizes inspectable cross-facet signals (pressure components, policy/verifier flags, grounding and relevance signals, interrupt recommendation, learning-event count, and internal-event queue/process flags) into a deterministic JSON-serializable shape. |
| **InterruptCandidate (Nexus v2)** | JSON-serializable record describing one potential interrupt (`source`, `interrupt_type`, scored `priority`, bounded `payload`, `cooldown_key`, etc.) extracted deterministically from current-cycle facet/LPB artifacts. Candidates are proposals only until Nexus applies suppression rules. |
| **SuppressionDecision (Nexus v2)** | JSON-serializable outcome for one candidate (`suppressed`, `suppression_reason`, triggered rule ids, cooldown/priority before/after, `allowed_internal_event`, and `allowed_user_expression`—**always false** in Nexus v2 interrupt rows; outbound expression is routed via **Expression Gate v0**, not interrupt suppression payloads). |
| **Nexus v2 interrupt arbitration** | Single-cycle, post-LPB pass that scores interrupt candidates, applies suppression (cooldown, duplicate, low priority, context overload, policy-denied ACT-path, max one internal event, max queue size), and may emit at most one `content="nexus_interrupt"` internal event. Not always-on, not autonomous speech, not tool execution. |
| **Expression Gate v0** | Support/control infrastructure (**not** a canonical facet): after final decision + verifier + interrupt/LPB artifacts, emits one JSON-safe **expression recommendation** (mode/score/intent/payload/metadata) separating internal interruption pressure from outbound expression. No LLM calls, no final prose generation, no printing/TUI/watch loop; unsolicited user-facing modes are cooldown- and budget-limited (`ExpressionBudgetState` under `facet_state["nexus"]["expression_gate"]`). Nexus v2 suppress rows keep `allowed_user_expression=false`; the gate’s `allowed_user_facing` flag is orthogonal and recommendation-only. |
| **ExpressionMode** | `silent`, `log_only`, `status_only`, `short_utterance`, or `ask_user` — deterministic v0 mapping from bounded score plus safety/policy/verifier floors. |
| **Presentation Vector v0** | Read-only deterministic projection (`fullerene/presentation/`) that turns per-cycle Nexus/runtime signals into a compact JSON UI packet (`PresentationVector`: mode, intensity, motion, channel, renderer-neutral animation hints). Not a canonical facet, not cognition, not emotion recognition, not an avatar/watch/TUI layer; does not write back into Nexus, facets, Memory, Policy, or stores. Optional Verifier helper `validate_presentation_vector_v0` checks shape when used. |
| **Latent Pressure Buffer (LPB)** | Signal infrastructure (not a canonical facet) that tracks unresolved pressure entries across cycles, applies conservative decay/escalation, computes bounded `latent_pressure_total`, and emits ignition recommendations as metadata only. LPB v1.1 adds idle `SYSTEM_TICK` ingestion gating + faster decay so routine echo signals do not self-reinforce latent pressure. LPB does not execute actions, does not speak, and does not run background loops. |
| **Conductor** | Deprecated harness-era name for the runtime loop; use **Nexus** for implemented runtime behavior. |
| **Event** | Typed runtime input such as a user message, system tick, or system note. |
| **Manual Tick Runner v0** | Explicit CLI-driven helper that runs one or more **`SYSTEM_TICK`** events via `NexusRuntime.process_event` (`--tick` / `--ticks` on `python -m fullerene`). For exercising internal state (LPB, interrupts, Expression Gate, verifier, persistence) without user prompts — not a daemon, scheduler, watch UI, or autonomous loop. Default tick metadata suppresses user-facing Expression Gate output (`suppress_expression`); `--allow-tick-expression` opts out. |
| **SYSTEM_TICK (manual)** | A `SYSTEM_TICK` event emitted by the Manual Tick Runner with JSON metadata (`manual_tick`, `tick_index`, `tick_count`, optional `tick_reason`, `suppress_expression`). Distinct from any future continuous “heartbeat” loop. |
| **Latent-only high pressure** | Tick-state where `system_pressure` is high mainly because `latent_pressure` is high, but no verifier-critical/policy-denied/danger signal is present. In v1.1 this no longer trips the short danger stop threshold. |
| **Watch Mode v0** | Terminal-facing CLI surface that runs **bounded, repeated** manual `SYSTEM_TICK` cycles and renders compact text snapshots (optionally JSON) of Fullerene’s pressure/latent pressure/expression/interrupt/presentation state. It is intentionally not an always-on daemon, not continuous loop v0, and does not generate autonomous user-facing speech. |
| **Continuous Loop v0** | Foreground-only bounded CLI loop (`--loop`) that executes repeated `SYSTEM_TICK` cycles at a fixed interval and renders minimal status (`mode`, `pressure`, `text/status`). Not a daemon/background service, not infinite by default, not LLM self-talk, and not autonomous tool execution. |
| **Interactive Loop v0** | Foreground-only bounded CLI loop (`--interactive`) that alternates repeated `SYSTEM_TICK` cycles with line-oriented user input. User lines are converted to normal `USER_MESSAGE` events (`interactive_input` metadata) and processed through Nexus/facets; not a daemon, not a full TUI, not autonomous tool execution, and not recursive self-talk. |
| **Behavior Facet** | Deterministic decision-policy layer that proposes whether Fullerene should `WAIT`, `RECORD`, `ASK`, or `ACT`, with inspectable score traces, conversational intent routing, grounding/ambiguity signals, and confidence breakdown metadata. `ACT` remains a typed proposal only (no autonomous execution/prose generation). |
| **Memory** | Structured, selective persistence for what Fullerene remembers; in v0 the canonical store is SQLite rather than a monolithic prompt file. |
| **Working memory** | Bounded packet of currently useful state assembled for the current cycle. In Context v1 this is not just a recent-memory slice; it is dynamically assembled from the current event plus active goals, memories, beliefs, policy summary, and compact signal summaries under deterministic limits. |
| **Episodic memory** | Append-only record of what happened; the primary source-of-truth event/history memory in v0. |
| **Semantic memory** | Persistent facts or beliefs distilled from experience; schema-supported in v0, but richer creation logic is deferred. |
| **Tag inference** | Deterministic, lowercase-rule mapping from event content to memory tags (Memory v1). No model calls. |
| **Salience** | Deterministic importance score in `[0.0, 1.0]` attached to a memory record. Memory v1 sums transparent signal boosts (user message, hard-rule-candidate, urgent, correction, authority, communication) over a base score and clamps. |
| **Hard-rule-candidate** | Tag for content that uses absolute language (`never`, `always`, `must`, `don't ever`); a flag for content that may eventually become a stored hard rule. |
| **Affect** | Fullerene's internal affective state vector, derived from its own cognitive activity rather than the user's emotions. Affect v0 is deterministic, inspectable, observation-only, and not sentiment analysis, emotion recognition, or a personality layer. |
| **VAD** | Common affect-space shorthand for **valence**, **arousal**, and **dominance**. Fullerene Affect v0 uses VAD plus novelty. |
| **Valence** | Internal positive-to-negative tone in `[-1.0, 1.0]`, derived in Affect v0 from goal progress, goal failure/staleness, feedback, and executor outcomes. |
| **Arousal** | Internal calm-to-activated level in `[0.0, 1.0]`, derived in Affect v0 from pressure, urgency/salience, and attention spikes when available. |
| **Dominance** | Internal sense of control vs overwhelm in `[0.0, 1.0]`, derived in Affect v0 from executor success/failure and world-model confidence signals when available. |
| **Novelty** | Internal familiar-to-novel score in `[0.0, 1.0]`, derived in Affect v0 from explicit novelty metadata or inverse memory retrieval hit rate when available. |
| **Attention** | Deterministic focus selection for what deserves foregrounding right now. Attention v1 is a fixed-weight spotlight selector with a bounded winner broadcast, conflict signal, and history, but it still does not mutate other facet stores. |
| **Bottom-up attention** | Attention mode driven more by novelty, surprise, or other immediate salience signals than by active-goal structure. In Attention v1 this is a deterministic classification, not a learned policy. |
| **Top-down attention** | Attention mode driven more by active-goal priority, goal alignment, or pressure tied to clear task structure than by raw novelty. In Attention v1, top-down wins close-score conflicts against bottom-up candidates. |
| **AttentionItem** | Inspectable scored focus candidate with `id`, `source`, optional `source_id`, `content`, weighted `components`, total `score`, a `dominant_component`, and metadata. |
| **AttentionBroadcast** | Inspectable winner packet emitted by Attention v1 with the winning item id/content/source, score, mode, recipients, repeated-attention pressure contribution, and any linked conflict ids. It is stored as metadata/state first, not as a direct cross-facet mutation. |
| **AttentionConflict** | Inspectable signal emitted when the top two attention candidates are within the configured close-score window (`0.05` in v1). It records the competing item ids, score delta, reason, and metadata. |
| **Attention history** | Bounded list of recent attention broadcasts. Attention v1 stores winners only, not every candidate, and uses that history to compute repeated-attention pressure contribution. |
| **AttentionResult** | Inspectable Attention output containing the selected top-N `focus_items`, per-candidate `scores`, optional `dominant_source`, strategy string, and metadata including broadcast, conflict, recipients, and bounded history count. |
| **Focus item** | A candidate that survives attention competition and lands in the selected top-N list for the current cycle. In Attention v1 the top focus item also becomes the broadcast winner when its score is positive. |
| **Broadcast** | The Attention v1 mechanism that pushes the winning focus item back into inspectable facet state and metadata so later facets can observe it without immediate store mutation. |
| **Context** | Current working packet of information available to Nexus, later facets, and CLI/model prompt grounding. Context v1 is deterministic, inspectable, bounded, and assembled from active state rather than static prompt text. |
| **Working context** | The concrete packet assembled for one Nexus cycle. It always includes the current event and may include active goals, relevant/recent memories, active beliefs, a compact policy summary, and compact signal summaries. |
| **Dynamic context assembly** | Deterministic bounded collection of context items from active stores/facet state using explicit limits, deduplication, simple ranking, and optional salience thresholds. It does not use embeddings, RAG, graph traversal, LLM summarization, or self-editing compression. |
| **ContextWindow** | Serialized context packet with `id`, `created_at`, `items`, `max_items`, `strategy`, and metadata. The current primary strategy is `dynamic_active_facets_v1`; `static_recent_episodic_v0` remains available for explicit compatibility. |
| **Context v2 (`pressure_relevance_v2`)** | Deterministic pressure/relevance-filtered context assembly strategy with protected inclusion for current event + same-session working memory, bounded budget selection, LPB/attention-aware inclusion, score breakdown metadata, and explicit exclusion/staleness traces. Not Memory v3 and not graph/community retrieval. |
| **Protected inclusion (context)** | Context items that bypass score competition/budget eviction until their bounded quota is met (current event and recent same-session working-memory turns in Context v2). |
| **Excluded context item** | Compact trace row for a candidate/prior item not included in the current context window (`stale`, `below_relevance_cutoff`, `budget_evicted`, `duplicate`, `wrong_session`, `low_pressure`). |
| **ContextItem** | One inspectable item inside a `ContextWindow`, with `id`, `item_type`, `content`, optional `source_id` / `created_at`, and metadata. Context v1 items can represent the current event, goals, memories, beliefs, policy summaries, or compact signal summaries. |
| **Belief** | Explicit persistent world-model record with `claim`, `confidence`, `status`, `tags`, timestamps, source metadata, and optional source links. |
| **World Model** | Structured belief store for what Fullerene believes about reality or tasks, separate from the event/memory log. World Model v1 is deterministic and SQLite-backed with belief confidence, contradiction/redundancy status, provenance, and lightweight edges; it updates confidence from support/contradiction heuristics and emits pressure signals, but still avoids clustering/graph traversal and LLM-generated belief extraction. |
| **Goal** | Explicit persistent record stored in SQLite with description, priority, status, tags, timestamps, source, and metadata. |
| **Goals** | Deterministic set of explicit goals that bias behavior and later planning. Goals v0 are inspectable and persistent; automatic goal inference is not implemented. |
| **Normalized goal key** | Deterministic normalized goal description used for duplicate detection: lowercase, trimmed, punctuation-stripped, whitespace-collapsed, and with common leading intent phrases such as `remember to`, `i should`, and `make sure` removed. |
| **Policy** | Deterministic permission and approval layer that constrains what Fullerene is allowed to do, forbidden from doing, or required to ask approval for. In v1 it evaluates explicit rules plus built-in sandbox defaults, emits structured `policy_evaluation` (with approval-token gating and `rule_precedence_trace`), and can aggregate per-step policy outcomes for `execute_plan`; it does not plan with an LLM, infer rules, or execute tools. |
| **Approval token metadata** | Explicit, locally validated approval metadata attached to an event (for example `event.metadata["approval"]`). In Policy v1 it gates `approval_required` outcomes without cryptography, persistence, or user identity systems. |
| **PolicyRule** | Explicit persistent policy row with `rule_type` (`allow`, `deny`, `require_approval`, `prefer`), `target_type`, `target`, `conditions`, priority, enabled/source flags, timestamps, and metadata. |
| **Sandbox** | The boundary around what Fullerene may manage directly without approval. In v0 the configured **state-dir** is the safe internal sandbox for self-managed runtime state. |
| **Repository state** | Gitignored `state/` at the repository root. Holds the default CLI `--state-dir` subtree, per-facet test trees (`mem_storage/`, `goals_storage/`, `world_model_storage/`), and other process-local files; see `fullerene.workspace_state`. Do not add new project-root dot-directories for runtime output. |
| **State-dir** | Explicit local directory that holds `state.json`, `runtime-log.jsonl`, and SQLite stores such as `memory.sqlite3`, `goals.sqlite3`, `world.sqlite3`, and `policy.sqlite3`. Internal CRUD inside this directory is allowed by default in Policy v0. The CLI default is `state/.fullerene-state` when `--state-dir` is omitted. |
| **Planner** | Deterministic plan-proposal layer that can emit inspectable next-step plans without executing them. Planner v0 is model-free, pressure-aware, and policy-filtered. |
| **Plan** | Inspectable proposed plan record with `id`, timestamps, optional source event / goal linkage, ordered `steps`, deterministic `confidence`, `pressure`, `status`, `reasons`, and metadata. |
| **PlanStep** | Inspectable ordered step inside a `Plan`, with description, `target_type`, `risk_level`, approval metadata, and step status such as `proposed`, `blocked`, or `requires_approval`. |
| **RiskLevel** | Deterministic planner/verifier risk label for a plan step: `low`, `medium`, or `high`. High-risk steps require approval before any future execution layer could act on them. |
| **Executor** | Deterministic manifest-backed execution layer. Executor v1 only invokes explicitly registered skills, defaults to dry-run, enforces policy and approval gates, supports sandbox-only file skills (`file_read`/`file_write`/`file_list`), halts on failure, and refuses shell/network/git/MCP/dynamic plugin execution. |
| **ExecutionRecord** | Inspectable per-step execution artifact with plan linkage, `status`, `dry_run`, `skill_name`, `skill_version`, `action_type_name`, `target_type`, policy/approval/sandbox metadata, retry/replan hints, and explicit reason codes. |
| **Skill registry (Executor v1)** | Explicit code/config manifest of permitted skills (`skill_name`, version, action/target support, dry-run/live support, approval/sandbox requirements). Unknown skills are refused and no dynamic skill loading is allowed. |
| **Executor sandbox** | Default `<state-dir>/sandbox` boundary used by file skills. Paths are normalized/resolved and must remain inside sandbox; traversal/absolute escapes are denied. |
| **File operation audit log** | Separate bounded executor log for sandbox file operations (`read`/`write`/`list`) with operation id, paths, bytes, dry-run flag, success, and reason/error; file contents are never logged. |
| **Dry-run** | Executor mode where Fullerene simulates supported actions and records what would happen without mutating state stores. Dry-run is the default for Executor v0, and switching to live mode does not broaden permissions. |
| **Helmet Rule** | Trust ladder for execution scope: v0 self-state only, v1 files and skills, v2 network/git reads, v3 real-world action. Trust is accumulated rather than assumed. |
| **Verifier** | Deterministic post-decision inspection layer that validates Fullerene's own runtime artifacts before persistence. Verifier **v1** keeps v0 checks (decision/facet shapes, policy compliance, `ACT` approval, deterministic plan-risk safety) and adds structured artifact/schema validation (Behavior traces, Nexus `verifier_cycle_context` / signal maps, Planner plans, Executor results, Learning v1 metadata, policy/context metadata rows). It recommends retry/escalation in metadata but performs no retries, no LLM calls, no external fact checks, no fuzzy grading, and no benchmark runner. |
| **Verifier v1.5** | Deterministic tightening pass on Verifier v1 that extends artifact consistency checks for Behavior v2.2 traces, Context v2 packets, World Model v1 belief artifacts, output metadata claim support, skill/executor result hooks, and cross-artifact policy/planner/executor consistency. Still no eval datasets, no LLM-as-judge, no prompt hardcoding. |
| **Verifier artifact check** | One JSON-serializable row emitted by Verifier v1 (`validator`, `artifact_kind`, `status`, `severity`, `code`, `path`, `message`, optional retry/escalation flags); many rows comprise `artifact_checks` / `schema_checks` on the facet summary. |
| **Unsupported capability claim** | Deterministic verifier finding raised when user-visible output text claims a capability/source class (web/tool/file/API/memory usage) but matching runtime metadata or traces are absent. |
| **Skill validator hook** | Verifier-side deterministic validator function keyed by skill/action name that checks executor result schema/consistency without invoking tools or models. |
| **verifier_cycle_context** | Nexus-injected snapshot on `facet_state["nexus"]` immediately before verifier facets run: canonical `signal_map`, `pressure_components`, learning-event list, queued internal events, facet order/results seen, and the pre-verifier `final_decision` string for deterministic schema validation without broad runtime refactors. |
| **VerificationResult** | Structured output from one deterministic verifier check: `check_name`, `status` (`passed`, `warning`, `failed`), `severity`, `message`, and metadata. |
| **Policy compliance** | Whether the final Nexus decision is structurally consistent with explicit policy outcomes such as `denied`, `approval_required`, or explicit `allow`, especially for side-effectful `ACT` decisions. |
| **Conversational intent (Behavior v2.1)** | Deterministic classification of the current conversational move (for example `follow_up`, `source_request`, `challenge`, `clarification_supplied`, `planning_request`) used to adjust decision routing and learning-event metadata. |
| **Behavior v2.2 lexical signals** | Deterministic numeric text features (`TextIntentScores` and related lexical scores) extracted in `fullerene/behavior/lexical.py`; lexical output is structured and does not emit final decisions. |
| **Response intent (Behavior v2.2)** | Metadata field derived from the selected decision/query intent (`answer`, `clarify`, `status`, `plan`, `memory_summary`, `acknowledge`, `none`), with `response_template` retained as compatibility metadata mapped from response intent. |
| **Grounding need (Behavior v2.1)** | Deterministic classification of what state/source is needed to answer confidently (`working_memory`, `memory`, `world_model`, `policy`, `runtime_state`, etc.), plus `grounding_available` and `grounding_confidence` fields. |
| **Ambiguity kind (Behavior v2.1)** | Inspectable ambiguity label (`none`, `generic`, `referential`, `missing_grounding`, `missing_action_target`, `repeated_unresolved`) used to avoid generic clarification loops when continuity or source/challenge intent is present. |
| **Confidence** | Deterministic inspection score (`confidence` and `confidence_breakdown`) attached to Behavior output; in v2.1 this includes grounding continuity/self-consistency components and challenge penalties. It is not ML probability or model uncertainty. |
| **Learning** | Stateless feedback router that observes explicit feedback and deterministic runtime outcomes, then emits traceable adjustment records or proposals. Learning v1 adds Nexus/Behavior trace ingestion, bounded Hebbian memory-edge strengthening on co-retrieved memories, conservative belief confidence adjustments, salience validation, and cross-facet routes (still no persistent Learning-owned store, no TD/meta/LLM). |
| **Cross-facet route** | Learning v1 inspectable record suggesting how a signal should flow (for example world-model contradiction toward behavior bias, or context overload toward consolidation); proposals are metadata-first and do not silently mutate foreign facets without an explicit store API. |
| **Co-retrieval set** | Bounded list of memory ids jointly surfaced in a cycle (Context `last_included_memory_ids` or Memory relevant/working ids). Learning v1 uses pairs only—never full-store scans—for Hebbian edge updates. |
| **LearningSignal** | Inspectable classified feedback artifact with `signal_type`, `source`, bounded `magnitude`, optional event/record linkage, metadata, and explicit reasons. |
| **AdjustmentRecord** | Inspectable adjustment artifact that names a target facet/field, records old/new values and delta when known, marks whether the change was applied, proposed, or skipped, and always points back to a `source_signal_id`. |
| **EMA** | Exponential moving average update rule. Learning v0 uses a conservative `alpha = 0.1` to compute a desired direction of movement before minor-nudge caps and proposal thresholds are applied. |
| **Proposal** | A non-applied adjustment suggestion emitted when the store/config surface is unavailable, the current value is unknown, or the requested change is too large to apply safely in v0. |
| **Skill** | Injectable capability (files, git, inbox, and so on) under policy control. |
| **Bob** | Example agent name from product vision; not a harness term. |
| **Stage** | Theater-model shorthand for Context. |
| **Spotlight** | Theater-model shorthand for Attention. |
| **Audience** | Theater-model shorthand for the facets that may eventually receive attention broadcast. |
| **Director** | Theater-model shorthand for Nexus as the global integration loop. |
| **Script** | Theater-model shorthand for Goals. |
| **Improvisation** | Theater-model shorthand for bottom-up salience and novelty signals that compete with top-down structure. |
| **Memory role** | Deterministic Memory v2 classification of a memory's purpose: `preference`, `fact`, `question`, `task`, `feedback`, `outcome`, or `unknown`. Stored on `MemoryRecord.role` and a `role` SQLite column, used as a hybrid-retrieval signal for role bonuses and penalties. |
| **Memory domain** | Coarse Memory v2 topic bucket inferred deterministically from content and tags (for example `reading_books`, `outdoors_water`, `project_software`, `task_work`). Stored on `MemoryRecord.domain` and a `domain` SQLite column. Domains are content-agnostic buckets, not hardcoded per-topic special cases. |
| **Query intent** | Deterministic Memory v2 classification of a query's purpose: `recommendation`, `planning`, `factual`, or `unknown`. Drives role bonuses and penalties during hybrid retrieval. |
| **Hybrid retrieval** | Memory v2 retrieval scoring that combines semantic similarity (`0.35`), tag overlap (`0.20`), salience (`0.15`), recency (`0.10`), domain match (`0.10`), and role bonus (`0.10`), minus role penalty. `explain_hybrid_score` exposes the per-component breakdown; the strategy degrades to deterministic v1 retrieval when embeddings are unavailable. |
| **Embedding index** | Optional Memory v2 vector index stored in a separate `memory_embeddings` table. SQLite remains the canonical memory store; the index is a non-authoritative similarity layer. `DeterministicHashEmbeddingProvider` is the offline-safe default and `OllamaEmbeddingProvider` is opt-in. |
| **EmbeddingProvider** | Memory v2 protocol with an `embed(text) -> list[float]` method, a `name`, and `dimensions`. `DeterministicHashEmbeddingProvider` produces stable token-hash vectors for tests/fallback; `OllamaEmbeddingProvider` calls a local Ollama embeddings endpoint when explicitly enabled. |
| **Memory edge** | Memory v2 inspectable directed link between two memory records, written at write time only to a bounded candidate set. Edge types include `same_goal`, `tag_overlap`, `temporal_proximity`, `keyword_similarity`, `semantic_similarity`, `same_domain`, and `role_related`. Edges are not yet traversed at retrieval time. |
| **Role bonus** | Hybrid-retrieval bonus that boosts memory roles aligned with the current query intent (for example, preference memory in the same domain on a recommendation query). |
| **Role penalty** | Hybrid-retrieval penalty that demotes unhelpful matches such as prior question memories on a recommendation query, duplicate recent question memories, or unanswered old question memories. |
| **Memory layer** | Memory v2.5 scope marker on each memory row: `long_term` (default durable Memory v2 behavior) or `working` (bounded session dialogue continuity records). |
| **Working turn** | Exact user/assistant/system conversational turn stored in Memory v2.5 working layer with `session_id`, `turn_index`, and `dialogue_role` metadata. |
| **Recent conversation packet** | Context v1.5-lite bounded chronological `working_memory` context items included before generic long-term memory retrieval for user-message grounding. |
| **Session id (interactive)** | Stable per-run id shared across all working-memory dialogue turns in one interactive loop execution. |
